# ADR-0005: UI シェルの構成と質感

- 状態: 採択
- 日付: 2026-09-22
- 前提: [ADR-0001](./ADR-0001-architecture.md), [ADR-0002](./ADR-0002-rendering-api.md)

## 決定

**3Dビューをウィンドウ全面に敷き、UI はその上に浮かぶ半透明のガラス面**として構成する。

- 画面下部中央に**フローティングのツールドック**
- 画面左に**レイヤーパネル**、画面右に**情報パネル**（どちらも折りたたみ可能）
- **設定画面は不透明**なモーダルにする
- **ダーク / ライト両対応**（OS 設定に追従）

## 背景

ADR-0001 で Tauri + React を選んだ最大の理由は「HTML を 3D の上に自由に重ねられる」ことだった。
このADRはその配当を実際に使う。子ウィンドウ方式（Bevy 案 / ネイティブ wgpu 案）では
**この構成自体が実現不可能**だった。

機能面の参照点は **Unreal Engine の LiDAR Point Cloud Plugin**。
同プラグインはグローバルな点予算で可視点を選ぶ方式を採っており、これは M1-4 で設計した
ものと同じ仕組みである。設計の妥当性が外部の実装でも裏付けられた形になる。

ただし UE のエディタ UI は**不透明なドック型クローム**であり、ここで採る Liquid Glass 的な
質感とは対極にある。**機能の水準は UE のプラグインを参照し、見た目は別の方針を採る**という
組み合わせであることを明記しておく。両者は独立に選べる。

## 引き受けた技術リスクと対処

### 1. `backdrop-filter` は毎フレーム再計算される

すりガラスは背景をぼかして合成するが、**背景が毎フレーム変化する 3D canvas では、
コンポジタがぼかしを毎フレーム計算し直す**。ガラスの面積とぼかし半径に比例して、
点群の描画そのものと GPU を奪い合う。

しかも**カメラを回している最中が点群描画の最も苦しい瞬間**であり、ここが重なる。

対処:
- **ガラスあり / なしでの fps を必ず実測する。** 推測で「大丈夫」としない
- ぼかし半径は控えめに始め、実測しながら上げる
- 実測の結果必要なら、**カメラ操作中だけぼかしを落として不透明寄りにする**
  （操作中は背景が流れるのでぼかしの見栄えへの寄与が小さく、失うものが少ない）

### 2. 点群の上ではガラスが読めなくなりやすい

Liquid Glass が成立するのは、背景が写真や壁紙のように**面として連続している**ためである。
点群はそうではない。

- 色が任意。RGB 点群では白い構造物の上に白い文字が乗りうる
- 高周波のノイズ。点の粒はぼかしを通しても残り、文字と干渉する
- **M2 で入れる EDL は点群のコントラストを上げる処理**であり、
  点群を読みやすくする処理がガラスを読みにくくする

対処:
- **ぼかしの下に必ず tint（単色の薄い層）を敷く。** 純粋な透明ガラスにはしない
- tint はテーマごとに別の値を持つ。**ライトテーマで暗い点群の上に白いガラスを置く構成が
  最も破綻しやすい**ので、ライトテーマの tint は特に検証する
- パネル内のテキストには十分なコントラスト比を確保する

### 3. ドック型はモードの状態が見えにくい

選択・計測・断面のような**モード切替式のツール**では、「いまどのモードか」が常に
見えている必要がある。横一列のドックはアイコンが並ぶだけなので、状態表現が弱い。

対処:
- アクティブなツールは明確なハイライト（背景色の変化＋インジケータ）で示す
- モード中はカーソル形状も変える
- ツール数が増えてドックに収まらなくなったら、この ADR を見直す

## 却下した案

| 案 | 却下理由 |
|---|---|
| 左に縦アイコンツールバー | 同種ツールの定石ではあるが、ガラス面積が大きくなり、全面ビューアの印象が弱まる |
| 上部に横ツールバー | 上下の縦幅を常に消費する。全面ビューア感が最も弱い |
| ダーク固定 | ライト対応のコストは認識した上で、両対応を選んだ |
| 透明度の高い強めのガラス | 点群の色が濃く透け、可読性が背景依存になる。`backdrop-filter` の負荷も上がる |
| 設定画面もガラス | 密な入力フォームは安定したコントラストが要る。ガラスに載せない |

## 帰結

**得たもの**
- 3D を遮らない UI。データを見るための画面という性格が保てる
- パネルを畳めば完全な全面ビューアになる

**払うもの**
- `backdrop-filter` の GPU コストを恒常的に抱える
- ガラスの可読性をテーマ 2 種類ぶん検証し続ける必要がある
- ドックのモード表現に追加の設計が要る
