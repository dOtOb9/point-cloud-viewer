# 再開時の引き継ぎ

中断して時間をおいてから作業を再開するとき、または新しいセッションで続きをするときに、最初に読むファイル。
「いま何がどこまで終わっていて、どこから読めば全体が分かり、次に何をすればいいか」を書く。
判断の理由や経緯は各 ADR・タスクシートにあるので、ここからは参照するだけにする。

**最終更新: 2026-10-11**（セッションを切り替える前にコーディネーターが更新）

## 0. 新しいセッションのコーディネーターへ

- まず `CLAUDE.md`（全エージェント共通の決まり）を読み、次にこのファイルを読む
- **役割分担**: 計画・診断・測定結果の解釈・判断は上位モデル（コーディネーター）が持ち、
  受け入れ基準を書いたうえで実装は Sonnet のサブエージェント（`model: sonnet`、`isolation: worktree`、バックグラウンド）に任せる。
  原因が分からない不具合の診断はコーディネーターの仕事。診断が終わったら、修正は委譲する
- 互いに独立した作業は並行で走らせる。所有者の確認を待って次を止めない
- **サブエージェントの報告は鵜呑みにしない。** スクリーンショットは自分でも見る、数値はヘッダーなどで突き合わせる。
  このセッションでも、エージェントの「動いた」の裏に別の不具合が何度も見つかった
- 使用量の上限（429）でエージェントが止まることが多い。止まったら `SendMessage` で同じエージェントを再開させる
  （途中の変更は worktree に残っている）
- 所有者は日本語で話す。返答も日本語

## 6. 所有者の好み・決めたこと（守り続けるもの）

- **所有者が実装を追えることが最優先**。記録は `TaskSheets/` に日本語で、1コミット1関心事
- 全体に関わる品質改善は、触るコードとその周りに少しずつ当てる（ADR-0015）。全体を一度に直さない
- 全エージェント共通の決まりは `CLAUDE.md` に書く（指示書に毎回書き写さない）
- **UI**: ガラス風（固定。スマホは性能のため自動で切る）、設定・進捗・エラーは中央のダイアログ（上にタイトル、下にボタン）、
  **パスを手で入力させない**（OS のファイル選択かドラッグ＆ドロップ）、ボタンはアイコン＋ラベル、
  色の役割は primary=緑・secondary=オレンジ・tertiary=グレー・error=赤、上や左の端に色の細い線、未実装の機能はグレーアウトで見せる
- 配色（標高・強度）は CloudCompare の既定（青>緑>黄>赤）。中央優先度の強さは 4 が既定
- 署名鍵は当面作らない。Web は GitHub Pages、インストーラーは Release の latest
- 動画では他社の UI・ブランドを映さない。未実装の機能を「できる」と言わない

## 7. 繰り返し踏んだ落とし穴

**すべて緑なのに壊れている**（このプロジェクトで最も多い）。画面が真っ黒、全ノードの読み込み失敗、Web の変換が必ず失敗、
変換の内訳が消える、EDL の黒い縁取り。**緑は「確かめた」の代わりにならない。** 画面で見る

**コーディネーターの仮説が外れる**（M4-13、M4-15 で連続）。仮説は「推定」と書き、計測で確かめてから直させる。
外れたときはエージェントに「仮説が外れたら直さずに止まって報告」と指示しておくと無駄が出ない

**一方向にしか動けず、回復経路を持たない設計**（ADR-0007、0010）。制御ループや推定を書くときは「下がったあと戻れるか」を確かめる

**測り方の誤り**。ピークメモリはワーキングセットではなく private memory で測る。エージェントの計測値は再現しないことがある。
Playwright のブラウザがソフトウェアの GPU（SwiftShader）で動いていないか、`adapter.info` で必ず確かめる

**エージェント同士がぶつかる**。古い preview サーバーを別のエージェントが掴む（ポートを `PCV_E2E_PORT` で分ける）、
`chrome.exe` や `node.exe` を一括で終了して他の作業や所有者のブラウザを止める（自分が起動したものだけ止める）

- CI の Rust ジョブは `vendor/copc-writer` の `cargo fmt` も別に検査する（push 前に CI と同じ手順を全部回す）
- 外部リポジトリへの提案・Issue・PR はしない
