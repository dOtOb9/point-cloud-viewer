  ノイズ点が1点あると範囲が広がって全体が一色に寄る。上下数%を切るパーセンタイル方式にする。
  所有者の実機で色が偏って見えたらこれが原因（`M2` M2-2）

  4GB の端末で 1GiB は多すぎる可能性が高い

`beer.laz` で変換コストを見積もるところから。今は COPC しか開けない。

### 小さい残務

## 4. 決めたこと（2026-09-23）

- **署名鍵は当面作らない**（`ADR-0004` 追記4）。その結果:
  - 更新は「起動時に最新版を確認して、同意があれば Release ページを開く」まで。自動適用はしない
  - Windows は SmartScreen の警告が出る
  - **Android はデバッグ鍵で署名している。** 鍵は CI のキャッシュ（`actions/cache`）に置いているが、
    **GitHub のキャッシュは7日間アクセスが無いと消える。** 消えると鍵が作り直され、
    次の版は古い版をアンインストールしないと入らない。確実に防ぐには鍵を1本作って Secrets に置くしかない
- **Web 版は GitHub Pages**。`pcv-core` を wasm にして Worker 内で同期 I/O で動かす（`ADR-0012`）
- **言語は TypeScript のまま**。肥大化の実体は言語ではなく1ファイルへの同居だったので、
  `point-cloud-renderer.ts` を3つに割った（`node-selection` / `gpu-resources` / 本体）
- **EDL の強度は 0.05 固定**（所有者の実機確認で決定）。スライダーは削除
- **配色は CloudCompare の既定（青>緑>黄>赤）**。所有者の「青→緑→赤」に、濁りを避ける黄色を挟んだ

## 5. 繰り返し踏んだ落とし穴

**一方向にしか動けず、回復経路を持たない設計**を3回踏んだ（2026-09-23）。

1. **ノードの読み出し** — レベル全体を空間クエリして大半を捨てていた（`ADR-0007` 追記）
2. **点予算** — vsync では「増やす」条件が原理的に成立せず、下がる一方だった（`ADR-0010`）
3. **リフレッシュ周期の推定** — 全期間の最小値で、異常に短い値を一度拾うと永久に固定された
   （`ADR-0010` 追記3）

新しく制御ループや推定を書くときは、「この値は下がったあと戻れるか」を必ず確認すること。

**すべて緑なのに壊れている**も繰り返した。

1. EDL の `depthStencil` 欠落 — WebGPU のバリデーションエラーはテストにも CI にも出ず、
   画面が真っ黒になった（`ADR-0011` の仕組みを入れた）
2. Release の添付 — ファイルが0件でも成功する設定で、**インストーラー抜きの Release が
   成功扱いで公開された**（`fail_on_unmatched_files: true` と成果物の列挙ステップを入れた）
3. 標高のカラーマップ — octree の立方体セルの範囲を標高の範囲に使い、全点が紫になった。
   テストは通っていた

緑は「確かめた」の代わりにならない。画面・実機・公開物を見るまでは未確認として扱う。

## 6. 守り続けている制約

- **秘密鍵・キーストア・パスワードは絶対にコミットしない。** 当面は作らない方針
- **点群データ（`*.laz`, `*.copc.laz`, `/data`）はコミットしない。** gitignore 済み
- コミットの著者は GitHub の noreply アドレスを使う
- 規約1〜4（`ARCHITECTURE.md`）は CI の `invariants` ジョブが機械的に検査する
- 実装は Sonnet に委譲し、計画・診断・検証を上位モデルが持つ
- **測っていないことを「実測した」と書かない**
- エージェント用の worktree は `.claude/` にでき、git・vitest・eslint の対象から外してある
