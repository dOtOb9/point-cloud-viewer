# ADR-0018: 機能は「選んだレイヤーから、新しいレイヤーを作る」向きに揃える

- 状態: 採択（設計の原則。この ADR の時点で、この原則に沿って作った機能はまだ無い）
- 日付: 2026-10-10
- 関連: [ADR-0017](./ADR-0017-ui-shell-ribbon.md)（UI シェル）、M4-14（複数ファイルの結合）

## 決定

点群に対する機能は、原則として次の形に揃える。

```
選んだレイヤー（1つ以上） ──操作──▶ 新しいレイヤー
```

- **元のレイヤーは書き換えない。** 結果はいつも新しいレイヤーとして、レイヤーの一覧に加わる
- 操作の対象は「いま選んでいるレイヤー」。リボンのツールは、選んだレイヤーに対して働く
- 新しいレイヤーは、どのレイヤーから何の操作で作ったかを持つ（あとで追えるように）

所有者の言葉: 「基本的に機能は選択したレイヤーから新しいレイヤーを作るという向きに統一する思想」。

## 当てはめの例（予定。どれも未実装）

| 操作 | 入力 | 出力 |
|---|---|---|
| 断面 | 選んだレイヤー＋断面の位置と厚さ | 断面の点だけのレイヤー |
| 範囲で切り出す | 選んだレイヤー＋範囲 | 範囲内の点のレイヤー |
| 分類で絞る | 選んだレイヤー＋分類 | その分類の点のレイヤー |
| 結合 | 選んだ複数のレイヤー | 1つにまとめたレイヤー |
| 計測 | 選んだレイヤー＋点の指定 | 計測結果のレイヤー（線や面） |

**今ある機能との関係:**
- 着色・EDL・点の大きさ・中央優先度などの**表示**の設定は、点群を作り替えないので、この原則の対象外。
- 複数のファイルを選んで1つの COPC にする機能（M4-14）は、「ファイルを開く」ときの処理なので、今はレイヤーの操作ではない。
- レイヤーを複数開けるようになったら、「選んだレイヤーを結合して新しいレイヤーを作る」形にも揃えられる。

## なぜこの形か

- **やり直せる。** 元を壊さないので、結果が気に入らなければ新しいレイヤーを消すだけで済む
- **操作をつなげられる。** 切り出した結果から断面を作る、というように、出力をそのまま次の入力にできる
- **何をしたかが残る。** レイヤーの一覧が、そのまま作業の記録になる

## 実装するときに守ること

- 新しいレイヤーの点群も、**メモリが点数に比例しない**ことを守る（CLAUDE.md）。数億点のレイヤーから切り出すときは、結果を COPC として一時領域に書き出し、そこから読む形を基本にする
- UI の部品は、今の段階から「選んでいるレイヤー」を中心に組む（ADR-0017 のレイヤー一覧）。未実装のツールのグレーアウト表示も、「選んだレイヤーに対する操作」として並べる
