# TP: 業務用の点群ソフト並みに使える操作を足す（視点・表示範囲・土量）

所有者の依頼（2026-11-16）: 「TREND-POINT のような品質の良い点群ビューアーにする」。
進め方は `AGENTS.md` の作業エージェント／監査役のループ（監査役が APPROVE するまで回す）。

## 今あるものと足りないもの

2026-11-16 の `main`（`d6a395f`）で、計測（距離・高さ・面積）・点の選択・断面（線・CSV/DXF 書き出し）・結合・
ラスタ（GeoTIFF）・間引き・外れ値の除去・DTM（CSF、LandXML）・着色（RGB/標高/強度/分類）・EDL はすでにある。
業務用の点群ソフトで毎日使う操作のうち、次の3つが無い。

| ID | 何を | なぜ |
|---|---|---|
| TP-1 | **視点**（全体表示・上/正面/側面/等角の定位置・平行投影） | 平面図・立面図として点群を見る、真上から計測する、迷ったら全体に戻る。HANDOFF 4章「`viewer.resetView` を呼ぶ UI が無い」もこれで閉じる |
| TP-2 | **表示範囲**（高さ・XY の範囲で描画を切る） | 屋根や木を消して地面だけ見る、建物の階ごとに見る。範囲をそのまま新しいレイヤーに切り出す |
| TP-3 | **土量計算**（多角形の範囲の、基準高に対する切土・盛土の体積） | 盛土・残土の数量を出す。業務用ソフトの主な用途の1つ |

等高線・点群の差分（ヒートマップ）は今回は扱わない（後で TP-4・TP-5 として起こす）。

## TP-1 視点

### 受け入れ基準

- **AC-1** リボンに「視点」ボタン（アイコン＋名前）。押すとダイアログ（HANDOFF 5章の形: タイトル上中央・ボタン下中央・✕なし・外をクリックで閉じる）で
  「全体」「上」「正面」「背面」「左」「右」「等角」と、投影「透視／平行」を選べる。レイヤーが1つも無いときはグレーアウト
- **AC-2** 「全体」は見えているレイヤー全部が画面に収まる位置へ移る（向きは今のまま）。見えているレイヤーが無ければ何もしない
- **AC-3** 定位置は上方向（`upAxis`。Z でも Y でも）に対して決める。「上」は真上から見下ろし、画面の上が北（上方向に直交する水平の基底のうち、Z-up なら +Y）。
  「正面」は南から北を見る（-Y 側から +Y 向き）。等角は yaw 45°・pitch 約35°。どれも注視点は見えているレイヤーの中心、距離は「全体」と同じ
- **AC-4** 平行投影。透視と切り替えても画面上の大きさがほぼ変わらない（切り替えた瞬間に注視点の位置での 1px あたりの長さが同じ）。
  平行投影でもホイールのズーム・パン・回転・ダブルクリックで寄る・**計測のピック**・**EDL**・**LOD の選択（画面空間誤差）**・グリッドが正しく動く。
  深度から距離を戻す式（`pick-math.ts`・`edl.ts`）は投影ごとに分けて、両方にテストを置く
- **AC-5** 移動はアニメーション（アニメーションが無効なら即時）。既存の `animateTo` を使う
- **AC-6** 視点を決める計算（定位置の yaw/pitch、全体の距離、平行投影の行列・大きさの対応）は `src/renderer/` の純粋な関数にしてテストを書く。
  ボタンを押したときの手順は `src/app/` の普通の関数（ADR-0021）

### 確かめ方（画面。作業エージェントは「未確認」と書く）

Web 版（`npm run dev`）で `autzen-classified.copc.laz` を開き、各定位置・平行投影で計測して、透視の時と同じ値になるか見る。

## TP-2 表示範囲

### 受け入れ基準

- **AC-1** リボンに「表示範囲」ボタン。ダイアログで、範囲を「高さ（上方向）」と「X」「Y」（水平の2軸）の下限・上限で決める。
  値は表示単位（m / ft、`useDisplayUnit`）。はじめは見えているレイヤーの範囲。高さは数値入力に加えて、ドラッグできる2つのつまみ（範囲スライダー）で動かせる
- **AC-2** 「範囲の内側だけ表示」「範囲の外側だけ表示」「切らない」を選べる。表示の設定なので、全レイヤーにかかり、元のレイヤーは変えない（ADR-0018 の対象外の側）
- **AC-3** 切るのはフラグメントの `discard` ではなく、**頂点シェーダーで範囲外の点を画面外（クリップ空間の外）に出す**か、または範囲がオフの時は今と同じパイプラインを使う形にする。
  どちらにしても、範囲を使っていない時の描画の速さが今と変わらないこと（`discard` を常に通るパイプラインにしない。gpu-resources.ts の既存の判断と同じ理由）
- **AC-4** 範囲の外にある点は、ピック（計測）・ダブルクリックで寄る・EDL の対象にもならない（深度に書かれない）
- **AC-5** 完全に範囲外のノードは選ばない（読み込みも要求しない）。「内側だけ」の時だけでよい
- **AC-6** ダイアログに「この範囲で新しいレイヤーを作る」。選んだレイヤーから、範囲の内側（または外側）の全点を新しいレイヤーとして作る。
  既存の切り出し（`pcv-core` の `extract`、`OrientedBox`）と既存の進捗ダイアログを使う。外側は、`ExtractFilter` に足りなければ足す（メモリが点数に比例しないこと）
- **AC-7** 大きな世界座標（例: 平面直角座標で X=−40000, Y=−10000、高さ 40m）で、範囲の境目が f32 の桁落ちで数 cm 以上ずれない（ノードの原点からの相対で比べるなど）。テストを置く

## TP-3 土量計算

### 受け入れ基準

- **AC-1** リボンに「土量」ボタン。押すと面積の計測と同じ操作で多角形を置く（既存の計測のピックを使う）。多角形を閉じたらダイアログが開く:
  対象レイヤー（選んでいるレイヤー。1つだけ選べる）、基準高（表示単位。初期値は多角形の頂点の高さの最小）、セルの大きさ（初期値 0.5 m 相当）、
  セルの代表値（平均／最低／最高。初期値は平均）
- **AC-2** 計算は対象レイヤーの**全点**（LOD の一部ではなく）で、多角形を鉛直に伸ばした柱の中の点を使う。各セルの代表値と基準高の差 × セルの面積を足して、
  **切土量（基準より上）・盛土量（基準より下）・差し引き・点のあったセルの面積・点の無いセルの割合**を出す。セルの中心が多角形の内側にあるセルだけを数える
- **AC-3** 計算は `crates/pcv-core` に置く（Tauri に依存しない、wasm でビルドできる、`Instant::now` を使わない）。既存の `ExtractPoints` で読む。
  **メモリはセルの数に比例し、点の数には比例しない**。セルの数に上限を置き、超えたら DTM と同じ形で、表示単位の数値の入った文で止める
- **AC-4** デスクトップ（Tauri のコマンド）と Web（Worker・wasm）の両方から呼べる。既存の DTM・断面の道筋に揃える。入口で panic を受け止めてエラーにする。
  wasm を作り直す（`npm run build:wasm`）
- **AC-5** 進捗と中止は既存の `ToolProgressDialog` を使う
- **AC-6** 結果は計測レイヤー（距離・面積の計測と同じ並び）として残り、ラベルに切土・盛土・差し引きを表示単位（m³ / ft³）で出す。
  点の無いセルが 10% を超えたら、結果に注意書きを出す（体積が小さめに出ている可能性）
- **AC-7** 合成データのテスト: 平らな地面（z=0）の上に、底面 10m×10m・高さ 2m の直方体の山（体積 200 m³）と、別の場所に深さ 1m の穴を置いた点群で、
  基準高 0、セル 0.5m で、切土・盛土がそれぞれ 1% 以内。多角形が凹形・点の無いセルがある場合も1つずつ
- **AC-8** 座標の単位が ft のファイルでは、体積を ft³ で計算してから表示単位に換算する（既存の `units.ts` の換算を使う）。テストを置く
