## 今あるものと足りないもの

2026-11-16 の `main`（`d6a395f`）で、計測（距離・高さ・面積）・点の選択・断面（線・CSV/DXF 書き出し）・結合・

| ID | 何を | なぜ |
|---|---|---|
| TP-1 | **視点**（全体表示・上/正面/側面/等角の定位置・平行投影） | 平面図・立面図として点群を見る、真上から計測する、迷ったら全体に戻る。HANDOFF 4章「`viewer.resetView` を呼ぶ UI が無い」もこれで閉じる |

## 共通: 使いやすさ（UX。TP-1〜TP-3 のすべてに当てはめる。所有者の依頼 2026-11-16）

機能が「ある」だけでなく、初めて触る人が迷わず使えることを受け入れ基準に含める。監査役はこの節も1つずつ確かめる。

- **UX-1 今どうなっているかが見える**: 視点（定位置の名前・透視／平行）と表示範囲（切っているか、内側／外側）をステータスバーなど常に見える所に出す。
  表示範囲で切っている間は「点が消えた」と誤解しないよう、目立つ表示と**1回で解除できる操作**を置く
- **UX-2 すぐ結果が見える**: 表示範囲のつまみ・数値は動かしたそばから描画に反映する（「適用」ボタンを押させない）。視点のボタンも押したらすぐ動く。
  ダイアログが邪魔で結果が見えない場合は、ダイアログを画面の端に寄せる・小さくするなど結果が見える配置にする
- **UX-3 次に何をすればよいか書いてある**: 多角形を置くツール（土量）は、置いている間、画面に操作の案内を出す
  （「クリックで頂点を追加・ダブルクリックか Enter で閉じる・Backspace で1点戻す・Esc でやめる」）。そのとおりに動くこと
- **UX-4 キーボード**: 視点は覚えやすいショートカット（例: `F` 全体、`1` 上、`2` 正面、`3` 右、`4` 等角、`5` 透視／平行の切り替え）。
  ツールチップにキーを書く。数値入力の中で打ったキーには反応しない。ダイアログは Enter で決定・Esc で閉じる、Tab で順に移れる
- **UX-5 入力の誤りはその場で**: 下限 > 上限、0 以下のセルの大きさ、空欄などは、入力欄の横に理由を出して実行ボタンをグレーアウトする（エラーダイアログに飛ばさない）。
  数値の横に必ず単位（m / ft、m³ / ft³）を書く
- **UX-6 元に戻せる**: 表示範囲は「初期値に戻す」ボタン。視点は「全体」で必ず戻れる
- **UX-7 タッチと狭い画面**: 押せる所は 44px 以上。幅 375px の画面でダイアログがはみ出さない。範囲のつまみはタッチでも動かせる
- **UX-8 言葉**: リボンの名前は短い日本語（2〜4文字）。業務用の点群ソフトで通じる言葉を使う（「切土」「盛土」「基準高」「平行投影」）。
  中の実装の言葉（ノード、LOD、NDC など）を画面に出さない

## TP-1 視点

### 受け入れ基準

- **AC-1** リボンに「視点」ボタン（アイコン＋名前）。押すとダイアログ（HANDOFF 5章の形: タイトル上中央・ボタン下中央・✕なし・外をクリックで閉じる）で
  「全体」「上」「正面」「背面」「左」「右」「等角」と、投影「透視／平行」を選べる。レイヤーが1つも無いときはグレーアウト
- **AC-2** 「全体」は見えているレイヤー全部が画面に収まる位置へ移る（向きは今のまま）。見えているレイヤーが無ければ何もしない
- **AC-3** 定位置は上方向（`upAxis`。Z でも Y でも）に対して決める。「上」は真上から見下ろし、画面の上が北（上方向に直交する水平の基底のうち、Z-up なら +Y）。
  「正面」は南から北を見る（-Y 側から +Y 向き）。等角は yaw 45°・pitch 約35°。どれも注視点は見えているレイヤーの中心、距離は「全体」と同じ
- **AC-4** 平行投影。透視と切り替えても画面上の大きさがほぼ変わらない（切り替えた瞬間に注視点の位置での 1px あたりの長さが同じ）。
  平行投影でもホイールのズーム・パン・回転・ダブルクリックで寄る・**計測のピック**・**EDL**・**LOD の選択（画面空間誤差）**・グリッドが正しく動く。
  深度から距離を戻す式（`pick-math.ts`・`edl.ts`）は投影ごとに分けて、両方にテストを置く
- **AC-5** 移動はアニメーション（アニメーションが無効なら即時）。既存の `animateTo` を使う
- **AC-6** 視点を決める計算（定位置の yaw/pitch、全体の距離、平行投影の行列・大きさの対応）は `src/renderer/` の純粋な関数にしてテストを書く。
  ボタンを押したときの手順は `src/app/` の普通の関数（ADR-0021）

### 実装の記録（作業エージェント R1、2026-11-16）

コミット: `7e61104`（renderer: 平行投影・定位置の計算）、`e41495d`（src/app/view.ts と状態）、`99a0b8a`（ボタン・ダイアログ・ステータスバー）。

**何をしたか**

- `src/renderer/projection.ts`（新規）: 透視・平行の投影をここに集めた。フレームごとに `Projection`（モード・行列・near/far・平行の見える高さ）を1つ作り、
  描画・ピック・EDL・グリッドはそれを読む。以前は `perspective(FOV_Y_RADIANS, …, NEAR, FAR)` が renderOnce・pickPoint・EDL・空とグリッドの基底に散らばっていた。
- 平行投影の大きさ: 見える高さの半分 = `distance * tan(fovY/2)`。透視で注視点の面に見える高さと同じなので、切り替えても注視点の位置の大きさが変わらない（AC-4）。
  平行ではホイールのズームがそのまま「拡大率」になる（`distance` が拡大率を兼ねる）。
- 平行の near/far: 注視点を中心に対称（`distance ∓ 2 * max(シーンの対角線, distance)`）。near は負になり、カメラの後ろの点も消えない。深度は線形になる。
- 深度から距離を戻す式を投影ごとに分けた: `pick-math.ts` の `depthToEyeDistance`（透視）／`depthToEyeDistanceOrtho`、`edl.ts` の `linearizeDepth`／`linearizeDepthOrtho`。
  ピックの2段目の near/far の絞り込みも平行用（`refineDepthRangeOrtho`。深度が線形なので距離によらず一定の幅）。
- EDL: 平行では目の距離が0や負になりうるので log2 が使えない。深度の差を注視距離で割った値（透視の log2 比の1次近似と一致）で比べる。
  `edlShadingFactorFromLogs` に式を1つにまとめ、透視・平行の両方がそこを通る。WGSL 側は `logDepth()`。
- グリッド: 平行ではレイの向きを視線に揃え、出発点を画素ごとにずらす（uniform の `params.w` が 1 のとき）。ずらす量は「画面の端までの実寸」で、
  既存の `viewRightScaled / viewUpScaled` に入れ替えて渡す。空は背景なので透視のレイのまま。
- LOD の選択（`screen-space-error.ts`）・視錐台カリング（`frustum.ts`）・レイ（`raycast.ts`）・計測の重ね描き（`screen-project.ts`）は、行列を通して計算しているので
  コードを変えずに平行で動く。これをテストで確かめた（`projection.test.ts`）。
- カーソル位置へのズーム: 平行ではどの画素のレイも向きが同じなので、そのままでは横に動かない。`getCursorDirection` が「視線 + カーソルの注視面でのずれ / distance」を返し、
  `OrbitCamera.zoom()` の「target を distance × (1 − 倍率) × この向きだけ動かす」計算で、ちょうどカーソル位置が動かないように寄る（正規化されていないベクトルを渡す）。
- ダブルクリックで寄る: 平行のレイの出発点は near 面（注視点の R だけ後ろ）なので、近くの箱の内側にならず、既存の `pickFlyToPoint` がそのまま使える。
- 定位置（`view-presets.ts`）: yaw/pitch を上方向から決める。北 = Z-up なら +Y、Y-up なら −Z、それ以外は `horizontalBasis` の right。
  上 = 正面と同じ yaw で pitch は上限（カメラは真上 90° を取れないので 89.4°）。等角 = 正面から東へ 45°・pitch 35°。
  注視点は見えているレイヤーの**ヘッダーの実データ範囲**の中心（octree の立方体ではない。立方体は高さ方向に引き伸ばされていて、正面・側面で中心がずれるため）。
- 全体の距離: `fitDistance`（透視: 外接球が収まる距離、平行: 見える高さの半分 ≥ 半径）。画面の縦横比も見る。
- `src/app/view.ts`（ADR-0021。React・ref なしの関数）: `showViewPreset` / `fitAllView` / `setProjection` / `runViewAction`。ボタン・ダイアログ・キーボードは全部 `runViewAction` を通る。
- UX: UX-1 ステータスバーに「視点: 正面（透視投影）」（狭い幅は「正面・透視」。実際のカメラから求めるので、回すと「自由」になる）。
  UX-2 ダイアログは押したらすぐ動き、開いたまま、画面の端（狭い幅は下）に寄せて暗幕を暗くもぼかしもしない（`Dialog` に `placement="side"` を足した）。
  UX-4 F=全体、1=上、2=正面、3=右、4=等角、5=投影の切り替え、6=背面、7=左。ツールチップとダイアログにキーを書いた。入力欄・Ctrl/Meta/Alt・IME変換中・キーの押しっぱなしでは反応しない。
  ダイアログの Esc・Tab は共通 `Dialog` のまま。UX-6 「全体」で必ず戻れる。UX-7 ボタンは `min-h-11`。UX-8 言葉は「視点・全体・上・正面・背面・左・右・等角・透視投影・平行投影」。

**採らなかった案**

- 平行を「FOV を極端に小さくした透視」で近似する案: 深度の精度が足りず（NEAR/FAR の幅が 1e9）、ピックと EDL の式がそのまま使えるように見えて桁落ちする。
- 平行の near を 0.01（透視と同じ）にする案: ズームでカメラが点群の中に入り、回すと後ろの点が消える。対称な near/far にした。
- EDL を平行でも log2(目の距離) のままにする案: near が負なので log2 が定義できない。
- 空も平行用に作り直す案: 空は向きを示す背景で、点群と位置を合わせる必要がない。グリッドだけ合わせた。
- 視点のダイアログを「選んで OK で適用」にする案: UX-2（すぐ動く）に反する。
- 全体の注視点・大きさに octree の立方体（`layerFocusBounds` の `sceneBounds`）を使う案: 上記のとおり高さ方向がずれる。

## TP-2 表示範囲

### 受け入れ基準

- **AC-1** リボンに「表示範囲」ボタン。ダイアログで、範囲を「高さ（上方向）」と「X」「Y」（水平の2軸）の下限・上限で決める。
  値は表示単位（m / ft、`useDisplayUnit`）。はじめは見えているレイヤーの範囲。高さは数値入力に加えて、ドラッグできる2つのつまみ（範囲スライダー）で動かせる
- **AC-2** 「範囲の内側だけ表示」「範囲の外側だけ表示」「切らない」を選べる。表示の設定なので、全レイヤーにかかり、元のレイヤーは変えない（ADR-0018 の対象外の側）
- **AC-3** 切るのはフラグメントの `discard` ではなく、**頂点シェーダーで範囲外の点を画面外（クリップ空間の外）に出す**か、または範囲がオフの時は今と同じパイプラインを使う形にする。
  どちらにしても、範囲を使っていない時の描画の速さが今と変わらないこと（`discard` を常に通るパイプラインにしない。gpu-resources.ts の既存の判断と同じ理由）
- **AC-4** 範囲の外にある点は、ピック（計測）・ダブルクリックで寄る・EDL の対象にもならない（深度に書かれない）
- **AC-5** 完全に範囲外のノードは選ばない（読み込みも要求しない）。「内側だけ」の時だけでよい
- **AC-6** ダイアログに「この範囲で新しいレイヤーを作る」。選んだレイヤーから、範囲の内側（または外側）の全点を新しいレイヤーとして作る。
  既存の切り出し（`pcv-core` の `extract`、`OrientedBox`）と既存の進捗ダイアログを使う。外側は、`ExtractFilter` に足りなければ足す（メモリが点数に比例しないこと）
- **AC-7** 大きな世界座標（例: 平面直角座標で X=−40000, Y=−10000、高さ 40m）で、範囲の境目が f32 の桁落ちで数 cm 以上ずれない（ノードの原点からの相対で比べるなど）。テストを置く

## TP-3 土量計算

### 受け入れ基準

- **AC-1** リボンに「土量」ボタン。押すと面積の計測と同じ操作で多角形を置く（既存の計測のピックを使う）。多角形を閉じたらダイアログが開く:
  対象レイヤー（選んでいるレイヤー。1つだけ選べる）、基準高（表示単位。初期値は多角形の頂点の高さの最小）、セルの大きさ（初期値 0.5 m 相当）、
  セルの代表値（平均／最低／最高。初期値は平均）
- **AC-2** 計算は対象レイヤーの**全点**（LOD の一部ではなく）で、多角形を鉛直に伸ばした柱の中の点を使う。各セルの代表値と基準高の差 × セルの面積を足して、
  **切土量（基準より上）・盛土量（基準より下）・差し引き・点のあったセルの面積・点の無いセルの割合**を出す。セルの中心が多角形の内側にあるセルだけを数える
- **AC-3** 計算は `crates/pcv-core` に置く（Tauri に依存しない、wasm でビルドできる、`Instant::now` を使わない）。既存の `ExtractPoints` で読む。
  **メモリはセルの数に比例し、点の数には比例しない**。セルの数に上限を置き、超えたら DTM と同じ形で、表示単位の数値の入った文で止める
- **AC-4** デスクトップ（Tauri のコマンド）と Web（Worker・wasm）の両方から呼べる。既存の DTM・断面の道筋に揃える。入口で panic を受け止めてエラーにする。
  wasm を作り直す（`npm run build:wasm`）
- **AC-5** 進捗と中止は既存の `ToolProgressDialog` を使う
- **AC-6** 結果は計測レイヤー（距離・面積の計測と同じ並び）として残り、ラベルに切土・盛土・差し引きを表示単位（m³ / ft³）で出す。
  点の無いセルが 10% を超えたら、結果に注意書きを出す（体積が小さめに出ている可能性）
- **AC-7** 合成データのテスト: 平らな地面（z=0）の上に、底面 10m×10m・高さ 2m の直方体の山（体積 200 m³）と、別の場所に深さ 1m の穴を置いた点群で、
  基準高 0、セル 0.5m で、切土・盛土がそれぞれ 1% 以内。多角形が凹形・点の無いセルがある場合も1つずつ
- **AC-8** 座標の単位が ft のファイルでは、体積を ft³ で計算してから表示単位に換算する（既存の `units.ts` の換算を使う）。テストを置く
