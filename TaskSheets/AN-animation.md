# AN: アニメーション（ゲームエンジンのような、なめらかな見え方と操作感）

- 状態: 計画（AN-1・AN-2 を先に進める。AN-3 は UI の作り直し（ADR-0017）が main に入った後）
- 日付: 2026-10-10
- 所有者の言葉: 「もっとゲームエンジン的に、アニメーションを使うとよいのでは？」

## 今の状態（コードで確かめた事実）

- 新しく読み込んだノードの点は、届いたフレームからいきなり表示される（ポップイン）
- カメラ（`orbit-camera.ts`・`touch-gesture.ts`）に慣性・なめらかなズーム・視点の移動のアニメーションは無い。
  指やマウスを離した瞬間に止まる
- UI のパネル・ダイアログの開閉にもアニメーションは無い

## 段取り

### AN-1: ノードのフェードイン（ポップインを無くす）

ゲームエンジンの LOD の切り替えと同じ手法を使う。**半透明で混ぜる（アルファブレンド）のではなく、
ディザ（画面上の決まった模様で一部の点を間引く）で、0.25 秒ほどかけて点を出していく。**

- なぜディザか: アルファブレンドは、点を奥から順に描かないと正しく混ざらない。数千万点を毎フレーム並べ替えるのは現実的でない。
  ディザなら、描くか捨てるかの二択なので、深度のテスト・EDL とそのまま両立する
- COPC は親のノードに子のノードの点を**足していく**形（親の点は残る）なので、要るのは「出る」側だけ。消える側のフェードは要らない
- ノードごとに「表示を始めた時刻」を持ち、シェーダーに経過の割合を渡す

### AN-2: カメラの動き

- **慣性**: 回転・パンの操作を離したあと、減速しながら止まる（マウスとタッチの両方）
- **なめらかなズーム**: ホイールの1段を、数フレームかけて目標の距離へ近づける
- **視点の移動のアニメーション**: 「全体を表示」（視点のリセット）と、ダブルクリックした点へ寄る（既存の `raycast.ts` を使う）を、
  ゆっくり始まりゆっくり止まる動き（イージング）で 0.4〜0.6 秒かけて移動する
- 慣性やアニメーションで動いている間も「カメラが動いている」と扱う（点予算の調整と、[HQ-2](./HQ-high-quality-mode.md) の「止まったら最大」の判定に効く）

### AN-3: UI の動き（UI の作り直しの後）

- ダイアログ: フェード＋少し拡大しながら出る（0.15 秒程度）。パネル: 横から滑り出る
- **動かすのは `opacity` と `transform` だけ。** ガラスの `backdrop-filter` の大きさやぼかしを動かすと、毎フレームの計算が重くなる（ADR-0005）

## 共通の決まり

- OS の「視差効果を減らす」（`prefers-reduced-motion`）が有効なら、動きを止める。設定にも「アニメーション: オン / オフ」を置く
- アニメーションの時間・減速の強さは定数にまとめ、**どれも未検証の初期値**と書く。所有者が画面で見て調整する
- スマホでも同じ動きにする。ただしフェードイン（AN-1）は、モバイルの GPU で重ければ切る（測ってから決める）
