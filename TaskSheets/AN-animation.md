# AN: アニメーション（ゲームエンジンのような、なめらかな見え方と操作感）

- 状態: 計画（AN-1・AN-2 を先に進める。AN-3 は UI の作り直し（ADR-0017）が main に入った後）
- 日付: 2026-10-10
- 所有者の言葉: 「もっとゲームエンジン的に、アニメーションを使うとよいのでは？」

## 今の状態（コードで確かめた事実）

- 新しく読み込んだノードの点は、届いたフレームからいきなり表示される（ポップイン）
- カメラ（`orbit-camera.ts`・`touch-gesture.ts`）に慣性・なめらかなズーム・視点の移動のアニメーションは無い。
  指やマウスを離した瞬間に止まる
- UI のパネル・ダイアログの開閉にもアニメーションは無い

## 段取り

### AN-1: ノードのフェードイン（ポップインを無くす）

ゲームエンジンの LOD の切り替えと同じ手法を使う。**半透明で混ぜる（アルファブレンド）のではなく、
ディザ（画面上の決まった模様で一部の点を間引く）で、0.25 秒ほどかけて点を出していく。**

- なぜディザか: アルファブレンドは、点を奥から順に描かないと正しく混ざらない。数千万点を毎フレーム並べ替えるのは現実的でない。
  ディザなら、描くか捨てるかの二択なので、深度のテスト・EDL とそのまま両立する
- COPC は親のノードに子のノードの点を**足していく**形（親の点は残る）なので、要るのは「出る」側だけ。消える側のフェードは要らない
- ノードごとに「表示を始めた時刻」を持ち、シェーダーに経過の割合を渡す

### AN-2: カメラの動き

- **慣性**: 回転・パンの操作を離したあと、減速しながら止まる（マウスとタッチの両方）
- **なめらかなズーム**: ホイールの1段を、数フレームかけて目標の距離へ近づける
- **視点の移動のアニメーション**: 「全体を表示」（視点のリセット）と、ダブルクリックした点へ寄る（既存の `raycast.ts` を使う）を、
  ゆっくり始まりゆっくり止まる動き（イージング）で 0.4〜0.6 秒かけて移動する
- 慣性やアニメーションで動いている間も「カメラが動いている」と扱う（点予算の調整と、[HQ-2](./HQ-high-quality-mode.md) の「止まったら最大」の判定に効く）

### AN-3: UI の動き（UI の作り直しの後）

- ダイアログ: フェード＋少し拡大しながら出る（0.15 秒程度）。パネル: 横から滑り出る
- **動かすのは `opacity` と `transform` だけ。** ガラスの `backdrop-filter` の大きさやぼかしを動かすと、毎フレームの計算が重くなる（ADR-0005）

## 共通の決まり

- OS の「視差効果を減らす」（`prefers-reduced-motion`）が有効なら、動きを止める。設定にも「アニメーション: オン / オフ」を置く
- アニメーションの時間・減速の強さは定数にまとめ、**どれも未検証の初期値**と書く。所有者が画面で見て調整する
- スマホでも同じ動きにする。ただしフェードイン（AN-1）は、モバイルの GPU で重ければ切る（測ってから決める）

### 何をしたか

**AN-1 フェードイン**
- ノードごとに「初めて描画対象になった時刻」（`CachedNode.firstDrawnAtMs`）を持ち、250ms で係数を 0→1 に上げる（`animation.ts` の `fadeInFactor`）。
  係数が 1 未満の間だけ、シェーダが画面位置の Bayer 4x4 のしきい値より小さい点を `discard` する（`gpu-resources.ts` の `fs_main_*_fade`）
- ノードごとの uniform（今までも毎フレーム `writeBuffer` していたバッファ）の末尾に `fade` を1つ足しただけ（80→96バイト）。
  バッファもバインドも増えないので、CPU側の追加コストはノードあたり引き算1回
- 取り消し（キャッシュから捨てて読み直し）されたノードは新しいエントリになるので、もう一度フェードインする

**AN-2 カメラの動き**（`orbit-camera.ts` に `update(dt)` を足し、`point-cloud-renderer.ts` が毎フレーム実際の経過時間で呼ぶ）
- 慣性: 離す直前100msのポインタ位置から速度を出し、`exp(-dt/τ)` で減衰。移動量は積分の閉じた式（`v·τ·(1-exp(-dt/τ))`）なので、フレームレートによらず同じ。
  新しい pointerdown で即停止。マウス左ドラッグ（回転）・中ドラッグ（パン）・指1本（回転）に効く。**2本指のパン/ピンチは指に追従させたいので慣性なし**
- なめらかなズーム: ホイール1段ごとに `log(倍率)` を「残り」に足し、指数的に消化。何段か重ねても掛け合わせた倍率が目標になる。ピンチは即時のまま
- 視点移動: `animateTo`（0.5秒、ease-in-out 3次）。距離は対数補間、yaw は近回り。「全体を表示」（`resetView`、新設）と、
  ダブルクリック/ダブルタップで寄る（`flyToScreenPoint`）に使う
- 寄り先: 描画中ノードの AABB へのレイキャスト（`raycast.ts` の `intersectRayAabb`）。交差する箱のうち**最も小さい箱**の交点を使い（`fly-to.ts`）、距離は現在の半分
- 「動いている」の一本化: `PointCloudRenderer.isCameraAnimating()`（統計にも `cameraAnimating`）。慣性・ズームの残り・視点移動のどれかがあれば true。
  **今の点予算の調整はカメラの動きを見ていないので、まだ使っていない**（HQ-2 や点予算の調整が使う入口として用意しただけ）
- 設定オフ / `prefers-reduced-motion` のときは、フェード係数は常に1、慣性なし、ズーム・視点移動は即時（今までと同じ）。OS設定は毎フレーム見る

### なぜその方法か（採らなかった案）

- ディザ vs アルファ: アルファブレンドは奥から順に描かないと正しく混ざらず、数千万点の並べ替えは非現実的。ディザは「描く/捨てる」の二択で、深度テスト・EDLがそのまま効く。
  欠点は、近づくと格子の模様が見えること（250msなので短い）
- `discard` を通常のシェーダに足さず、フェード用のパイプラインを別に4つ作った: M3-8 のコメントのとおり、`discard` があるだけでタイルベースGPUの Early-Z が効きにくくなるため。
  落ち着いたノードは今までのパイプラインのまま描き、フェード中のノードだけ後からまとめて描く
- 慣性・ズームを「毎フレーム 0.95 倍」にしなかった: フレームレートで挙動が変わるため。`exp(-dt/τ)` の形ならどのレートでも同じ
- 寄り先に `closestHierarchyHit`（最も近い交点）を使わなかった: 描画中のノードには粗い親も含まれ、最も近い交点は常に最も粗い外側の箱になる。
  さらに COPC の箱は立方体で実データより高く、**実ブラウザで試したら、データの上端615に対して z=1570 の空中の面に寄った**。
  そこで箱を LAS ヘッダーの実データ範囲で切ってから判定する（`setElevationRange` で受け取った範囲を使う）。箱の面は点そのものではないので、寄り先は「だいたいその辺」
- 既存の `getCursorDirection`（ホイール用）は CSS px をそのままバッファ解像度として使っており、レンダースケール≠1 で位置がずれる。**これは既存の挙動なので触っていない**。
  寄り先の計算 (`flyToScreenPoint`) は換算してから使っている

### 確かめていないこと

- Android・タッチの手触り（慣性の強さ、ダブルタップの間隔 300ms・30px、ズームの速さ）。タッチのダブルタップは単体テスト・実機とも**未確認**（実ブラウザの確認はマウスのみ）
- 高負荷（vsync を割る重い点群）でフェードがフレーム時間に与える影響。モバイルGPUでの負荷（AN の共通の決まりでは「重ければ切る」。測っていない）
- ディザの見た目の好み（250ms が長い/短い、模様が目立つか）
- `prefers-reduced-motion: reduce` の実ブラウザでの確認（単体テストで関数の分岐だけ確認）
- 点予算の調整が `isCameraAnimating()` を見るようにする件（未着手）

### 所有者の確認手順

1. `npm run dev` で開き、点群を読み込む。新しいノードが出るとき、格子状にスッと現れて 0.25 秒ほどで埋まること
2. 左ドラッグ → 勢いよく離す → ゆっくり止まること。止まる前にクリックすると即座に止まること
3. ホイールを1段回す → 数フレームかけて寄ること。何段か続けても自然なこと
4. 点群の上をダブルクリック → その点へ 0.5 秒ほどで寄ること（空中に寄らないこと）
5. 実機（スマホ）でダブルタップ、指1本のフリック、ピンチ
6. OS の「視差効果を減らす」をオンにして、すべて今までどおり即時になること
7. 調整は `src/renderer/animation.ts` の定数を変えて見比べる
