# HQ: 高品質モード（PC のメモリと GPU の余裕を使って、もっと細かく表示する）

- 状態: 計画（HQ-0 から順に進める。各段の終わりに判断点がある）
- 日付: 2026-10-10
- 対象: デスクトップ版と、PC のブラウザの Web 版。**スマホ・モバイル Web は対象外**（今の保守的な設定のまま）
- 関連: [ADR-0009](./ADR-0009-adaptive-render-settings.md)・[ADR-0010](./ADR-0010-lod-priority-and-point-budget.md)（点予算と AIMD）・[ADR-0011](./ADR-0011-gpu-error-visibility.md)（GPU の喪失）・[ADR-0017](./ADR-0017-ui-shell-ribbon.md)（設定画面）

## 背景: 今の状態（コードで確かめた事実）

- 点予算の上限（デスクトップ）は、GPU メモリ **1GiB** を前提にした計算で決まる固定値で、約2,684万点。
  計算は `上限 = 1GiB ÷ (1点のバイト数 × 2)`（`device-profile.ts`・`point-budget.ts`）。
  2倍なのは、GPU 上のノードのキャッシュを点予算の2倍まで持つため（`CACHE_BUDGET_MULTIPLIER`）
- 点予算は、上限から始まり、フレームが間に合わなければ下げる（AIMD、ADR-0010）
- 一度読んだノードは GPU メモリにしか置かない。キャッシュから外れたノードは、もう一度ファイルから読み、展開し直す。
  **PC の RAM はほとんど使っていない**
- 動画の撮影時（渋谷 3.48 億点、この開発機の Chromium）の画面では、`pointBudget` が上限 26,843,545 に張り付いたまま fps 60 だった。
  **上限がブレーキになっている可能性が高い。ただし1枚の画面からの読みで、測ったものではない**（HQ-0 で確かめる）

## 引き受けるリスク

1. **GPU の喪失（device lost）が増えるおそれ。** 所有者の Windows でも、ときどき GPU が落ちる件が未解決のまま残っている。
   GPU メモリを多く使えば、落ちやすくなる可能性がある。
   → 段階的に上げて測る。落ちたら標準に戻して、そのことを画面に出す（ADR-0011 の仕組みに乗せる）
2. **WebGPU では GPU メモリの量（VRAM）が分からない。** 自動では決められない。
   → 使ってよい量は、所有者が設定で選ぶ。選べる上限は `adapter.limits` と、HQ-1 の実測で決める
3. **止まったときに最大まで描くと、次に動かした最初のフレームが重くなる。**
   → 入力を受けた時点で、描く前に点予算を戻す（HQ-2）

## 段取り

### HQ-0: 測る（コードは main に入れない）

開発機は所有者の PC と同じ（Core i5-14600K / RTX 4070 / 31.8GB）。Playwright の画面ありの Chromium で、**実際の GPU が使われていることを確かめたうえで**（SwiftShader ではないこと）測る。

- データは `data/tokyo-shibuya-merged.copc.laz`（3.48 億点）。視点は3つ固定する: 全体を見下ろす、街区、通りの高さ
- 上限を 1・2・4・8 GiB 相当に変えて（一時的な改造。コミットしない）、各視点で 10 秒止めたあとの値を記録する:
  `pointBudget`・上限・描いた点数・fps・読み込み待ちのノード数・GPU が落ちたか
- 5分間カメラを回し続けて、GPU が落ちないかも見る

**判断点 A**: 上限を上げると、描く点が増えて fps が保てるか。
- 増えないなら、ブレーキは別の場所にある。HQ-1 はやめて、原因を調べる
- 増えるなら、HQ-1 の選択肢（何 GiB まで選べるようにするか）を、この結果から決める

### HQ-1: 使ってよいメモリの量を選べるようにする

- 設定に「画質: 標準 / 高品質」を加える。高品質にすると、GPU メモリの予算を選べる（選択肢は判断点 A で決める。標準は今の 1GiB）
- 予算を変えたら、点予算の上限とキャッシュの大きさに反映する（再起動なし）
- GPU が落ちたら、標準に戻して、ダイアログで知らせる
- 設定画面は UI の作り直し（ADR-0017）の後に触る。それまでは、レンダラーと状態の側だけを作る

### HQ-2: 止まったら最大の細かさまで読む

- カメラが一定時間（初期値 0.5 秒、要調整）動かなかったら、AIMD による点予算の調整を止め、上限まで点予算を上げて読み込む
- 入力（ドラッグ・ホイール・タッチ）を受けたら、その時点で、描く前に元の点予算に戻す
- 測る: 止めてから最大の細かさになるまでの時間、止めている間の fps、動かし始めた最初のフレームの時間

**判断点 B**: 高品質モードを、デスクトップの既定にするか（所有者が画面で見て決める）。

### HQ-3（判断点 B の後に決める）: 展開済みのノードを RAM に置く

- GPU のキャッシュから外れたノードを、RAM に数 GB まで置いておく。戻ってきたときに、ファイルの読み込みと展開を省ける
- 効くのは細かさではなく、**戻ったときの速さ**。HQ-1 と HQ-2 を体感してから、要るかを決める

### 採らない（今は）: fps の目標を 60 から 30 に下げる

描ける点は増えるが、操作が重くなる。HQ-2（止まったら最大）のほうが、操作感を落とさずに細かさを上げられる。
HQ-2 の結果を見てから考え直す。

## 所有者が確かめること（各段の後で、手順は各段の記録に書く）

- HQ-1・HQ-2: 渋谷のデータで、標準と高品質の見た目の差。GPU が落ちないか
