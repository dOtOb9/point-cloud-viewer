# ADR-0014: UI シェルのレイアウトを ui-forge の `.ui` ファイルで書く

- 状態: 採択（まず `Dock` だけ。広げるかは I-1 の結果を見て決める）
- 日付: 2026-10-03
- 前提: [ADR-0005](./ADR-0005-ui-shell.md)（UI シェルの構成と質感）
- 関連: ui-forge の [ADR-0001](https://github.com/dOtOb9/ui-forge/blob/main/TaskSheets/ADR-0001-design.md)

## 決定

UI シェルの部品のうち、**レイアウトと見た目は ui-forge の `.ui` ファイル（JSON）に書き、
ui-forge が生成した TSX を使う。** 状態とロジックは今まで通り手書きの TSX に置く。

最初は `Dock` だけを置き換える。

```
src/ui/shell/
  Dock.ui              レイアウトと見た目（正）。ui-forge のプレビューで開いて確かめ・編集する
  Dock.generated.tsx   Dock.ui からの生成物。手で編集しない。CI で最新かを検査する
  Dock.tsx             薄い包み。glassEnabled → surface の変換など、ロジックだけを持つ
```

`AppShell.tsx` から見た `Dock` の props は変えない。

## 背景

AI に UI を書かせると、その場では動いても、人間が追えない形で膨らみやすい。
JSX の中ではレイアウトとロジックが混ざり、レイアウトの正しさを読み取るのも重い。

ui-forge は、レイアウトを語彙の限られたテキストに書かせ、人間はプレビューで見て確かめ、
差分でレビューする道具として、このプロジェクトのために作った（経緯は ui-forge の ADR-0001）。

## なぜ `Dock` から始めるか

- 一番小さく、状態が少ない（開閉の 2 つとボタン 3 つ）
- 現在の語彙（`Canvas` / `HBox` / `Panel` / `Button`）だけで表せる。`LayerPanel` や
  `SettingsModal` はスライダー・セレクトなどの語彙が要り、まだ表せない
- 置き換えの前後で見た目が変わらないことを、クラス単位で確かめられる

## 引き受けること

- **ビルドの道具が 1 つ増える。** ui-forge を git の依存として入れ、CI で生成物の同期を検査する
- **生成物をリポジトリに入れる。** `.ui` を変えると、生成物の差分も一緒に出る
- **DOM が 1 段深くなる。** 生成物は `Canvas`（`fixed inset-0` の層）の中にドックを置くため。
  見た目とクリックの挙動は変わらない（`Canvas` の層は `pointer-events-none`）

## 広げるかどうかの判断基準

`Dock` を置き換えた後、次を満たすなら他のパネルにも広げる（語彙の追加は ui-forge 側で行う）。
- 所有者が `.ui` とプレビューを使って、`Dock` の見た目を実際に変えてみて、TSX を直接直すより
  追いやすいと感じた
- CI の生成物同期検査が、運用の負担になっていない

満たさなければ、`Dock.generated.tsx` の中身を手書きの `Dock.tsx` に戻して ui-forge を外す
（生成物は普通の TSX なので、戻すのは簡単）。

## 却下した案

| 案 | 却下理由 |
|---|---|
| 実行時に `.ui` を解釈する | 型の保証が弱く、Tailwind のクラス検出も別の設定が要る（ui-forge ADR-0001 と同じ） |
| ui-forge をこのリポジトリに同居させる | 本体の履歴にツールの変更が混ざる。ui-forge を独立リポジトリにした理由そのもの |
| `Dock.tsx` そのものを生成物にする | ロジック（`glassEnabled` の変換）を `.ui` に書く手段が無く、書けるようにすると ui-forge に Graph 相当を作ることになる |
