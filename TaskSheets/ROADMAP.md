足りない土台が既存の設計と衝突するなら、そこで ADR を見直す。

## 土台（複数の機能が共有するもの）

将来機能の多くは、この5つのどれかに帰着する。**個別に作らず、土台として一度作る。**

| 土台 | 現状 | これを必要とする機能 |
|---|---|---|
| **空間クエリ層**（`pcv-core`） | **無い。** 現 API は `open / info / hierarchy / read_node` のみ | 範囲限定処理、断面抽出、選択、クリッピング、TIN 生成の入力 |
| **ピッキング**（クリック位置の3D点） | **無い。** octree への CPU レイキャストが素直 | マーカー配置、計測、選択、歩行時の接地 |
| **メッシュ描画パイプライン** | **無い。** 現在は point sprite 専用 | TIN 表示、断面の面表示、将来のメッシュ化 |
| **カメラのナビゲーション** | **不十分。** 固定の注視点に漸近するだけで、カーソル位置に寄れない（[M1-5](./M1-point-rendering.md) で対処） | あらゆる目視検証の前提。EDL・カラーマップ・計測の評価もこれに乗る |
| **2D プロファイル描画** | 無いが、HTML/SVG で素直に書ける | 断面図、ヒストグラム、時系列 |

## 想定している将来機能と、必要な土台

### 断面線を引く

3Dビュー上で線を引き、鉛直面の近傍点を抽出して 2D プロファイルとして別パネルに描く。

- 必要な土台: **空間クエリ層**、**2D プロファイル描画**
- 構成との相性: **最も良い。** 2D の軸・目盛り・寸法線・エクスポートは HTML/SVG の得意分野で、
  これは [ADR-0001](./ADR-0001-architecture.md) で Bevy を却下して得た能力そのもの。
  [ADR-0005](./ADR-0005-ui-shell.md) のガラスパネル構成にそのまま乗る

### マーカーを置いて、その範囲内だけを処理する

3Dビューをクリックして位置を確定し、その周囲の範囲に処理を限定する。

- 必要な土台: **ピッキング**、**空間クエリ層**
- 構成との相性: 良い。クリッピングボリューム（UE 参照）と選択（M5）と**同じ土台に乗る**ので、
  空間クエリ層を一度作れば3機能が同時に前進する

### DTM の TIN を生成して、その上を歩く

地面点を分離し、TIN を生成し、一人称視点でその上を歩く。

- 必要な土台: **空間クエリ層**、**メッシュ描画パイプライン**、**ピッキング**（接地判定）
- 構成との相性: **ここだけ現状のままでは乗らない。** 下記参照

#### なぜ今のままでは乗らないか、と、その手当て

**レンダラが点しか描けない。** M1 で作っているのは point sprite パイプライン専用である。
TIN は三角形メッシュなので第2のパイプラインが要る。追加自体は難しくないが、
**レンダラが「点群を描くもの」として書かれていると、後から構造ごと作り直しになる。**

→ **M1 のスコープは守り、M2 で「描画対象の種類を分ける」構造の手当てを入れる。**
今なら安く、機能が増えてからでは高い。M2 の作業として明記すること。

**ノードのバイナリ形式が点専用** — こちらは手当て済み。ヘッダに `magic "PCVN"` と
`version` を入れてあるため、メッシュ用に `"PCVM"` を追加できる。
形式を versioned にしておいた判断がここで効く（[M1](./M1-point-rendering.md) 参照）。

**「歩く」部分は軽い。** TIN への高さクエリ＋一人称カメラで済む。
ゲームエンジンを使わない判断がここで響くことはない。Bevy を採用していても TIN 生成も
点群 LOD も得られず、キャラクターコントローラは点群の上を歩くには結局自前調整になる。
[ADR-0001](./ADR-0001-architecture.md) の判断は変わらない。

**難所は描画ではなく生成側。** 大面積の out-of-core Delaunay 三角形分割は、
[M4](./M4-import-and-conversion.md) で問題にした octree 構築と同じ難度クラスである。
着手するときは M4 と同じく、**素朴な実装で測ってから方式を決める**こと。

### 選択・編集・クリッピング（M5、UE の LiDAR Point Cloud Plugin 参照）

ボックス／多角形で点を選び、削除または別レイヤーに抽出する。
範囲の内側／外側を非表示にするクリッピングボリューム。法線計算。

- 必要な土台: **ピッキング**、**空間クエリ層**
- 構成との相性: 良い。上記2機能と土台を共有する

## 想定していないもの

範囲を明示しておく。これらが必要になったら、その時点で ADR を起こして判断し直す。

- コリジョン生成、Blueprint 相当のスクリプティング（UE 固有で、解析ツールには不要）
- 点群からの本格的なメッシュ化（Poisson 再構成など）
- リアルタイム協調編集
