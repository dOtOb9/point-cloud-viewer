# PF: 初めて開いたときに、すぐ点群が見えるようにする（落ちない範囲でメモリを先に使う）

所有者の依頼（2026-11-16）: 「点群の初回読み込み時の遅さが問題だ。メモリに余裕があるなら、初回はメモリに乗せるなど描画を優先し、
その後にディスクに書き出すなどの処理が追いついてメモリ消費量が減少するようなアーキテクチャを構成すべきではないか。
いずれにしても、アプリが落ちるなど、UX を損なうような挙動は避けるべきだ」。

## 今の形（コーディネーターが文書から読んだもの。数値は既存の記録の引用で、今回は測っていない）

- LAS/LAZ/PLY/PCD/E57 は、COPC への変換（`copc-writer` の out-of-core、ADR-0006・ADR-0019）が**全部終わってから**開く（R11: 開くのは変換を await する）
- 既存の記録: sofi 3.64 億点の変換に 1,079 秒（ADR-0006 の M4-1b、旧方式）、渋谷 3.48 億点で 241 秒（ADR-0019 の後）。その間、画面には何も出ない
- COPC は変換なしで開ける。ただし初回の表示までの時間（ヘッダー・階層の読み込み、最初のノード）が十分速いかは、今回の依頼の範囲で測り直す

## 目標

1. **最初の点が見えるまでの時間**を、入力の大きさにほとんど依らない数秒にする（LAS/LAZ で、変換の完了を待たない）
2. 変換が進むにつれて表示が細かくなり、終わったら今の COPC の表示に**途切れずに**切り替わる
3. **メモリは使ってよいが、落ちない。** 端末のメモリ（デスクトップは物理メモリと空き、Web は `navigator.deviceMemory` と wasm32 の 4GB、Android は小さい）から上限を決め、
   上限に近づいたら先に表示用のメモリを手放す。変換が追いついたらメモリを返す
4. 失敗しても固まらない。変換が失敗・中止されても、それまでに見えていた表示は残り、エラーを既存の表示に出す

### PF-0 R2・R3 での設計の変更（作業エージェント）

- R2（監査 F-1〜F-10）: 数値を出力に合わせて直した（Web のピークの桁区切りの読み誤り、最初のノードの読み出し時間）。ADR-0024 に、レンダラへの階層差し替えの口、切り替えの条件、変換の入口 5 つ、空きに応じたメモリ、ADR-0022/0023 との整合、PF-1 の受け入れ基準の案を足した

  変換のメモリ予算（開始時に空きから決め、途中は下見と NodeCache だけで応える）、PF-1 の範囲（単一 LAS/LAZ に絞る。10 枚・55 枚は PF-2）に直した。詳しくは ADR-0024
- AC-4 の現在の要約: 下見の目標点数は空きメモリ A から `clamp(A×4%÷20B, 50万点, pointBudgetMax/2)`、逼迫したら 下見 → NodeCache（setPointBudget）の順に手放す。Web/Android は固定で、変換のメモリを悪化させない（ADR-0024「メモリ」）。
