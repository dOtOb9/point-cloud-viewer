# PF: 初めて開いたときに、すぐ点群が見えるようにする（落ちない範囲でメモリを先に使う）

所有者の依頼（2026-11-16）: 「点群の初回読み込み時の遅さが問題だ。メモリに余裕があるなら、初回はメモリに乗せるなど描画を優先し、
その後にディスクに書き出すなどの処理が追いついてメモリ消費量が減少するようなアーキテクチャを構成すべきではないか。
いずれにしても、アプリが落ちるなど、UX を損なうような挙動は避けるべきだ」。

## 今の形（コーディネーターが文書から読んだもの。数値は既存の記録の引用で、今回は測っていない）

- LAS/LAZ/PLY/PCD/E57 は、COPC への変換（`copc-writer` の out-of-core、ADR-0006・ADR-0019）が**全部終わってから**開く（R11: 開くのは変換を await する）
- 既存の記録: sofi 3.64 億点の変換に 1,079 秒（ADR-0006 の M4-1b、旧方式）、渋谷 3.48 億点で 241 秒（ADR-0019 の後）。その間、画面には何も出ない
- COPC は変換なしで開ける。ただし初回の表示までの時間（ヘッダー・階層の読み込み、最初のノード）が十分速いかは、今回の依頼の範囲で測り直す

## 目標

1. **最初の点が見えるまでの時間**を、入力の大きさにほとんど依らない数秒にする（LAS/LAZ で、変換の完了を待たない）
2. 変換が進むにつれて表示が細かくなり、終わったら今の COPC の表示に**途切れずに**切り替わる
3. **メモリは使ってよいが、落ちない。** 端末のメモリ（デスクトップは物理メモリと空き、Web は `navigator.deviceMemory` と wasm32 の 4GB、Android は小さい）から上限を決め、
   上限に近づいたら先に表示用のメモリを手放す。変換が追いついたらメモリを返す
4. 失敗しても固まらない。変換が失敗・中止されても、それまでに見えていた表示は残り、エラーを既存の表示に出す

## 段階

### PF-0 計測と設計（コードは変えない。成果は文書）

- **AC-1** 今の「ファイルを選んでから最初の点が描かれるまで」と「全部見えるまで」の時間、ピークメモリ（private）を、
  `autzen-classified.copc.laz`（COPC）・autzen の LAS（無ければ `merge_las_to_copc` の入力に使った LAS の1枚）・渋谷の LAS 1枚（約 620 万点）・渋谷 55 枚の結合で、
  デスクトップ（Tauri、または同じ Rust を呼ぶ example）と Web（Playwright の実 GPU のブラウザ）で測る。P コアに固定する（CLAUDE.md）。
  大きな入力は run_in_background。ディスクの空き（推定ピーク＋25GB）を先に確かめる
- **AC-2** どこで時間を使っているかの内訳（読み込み・LAZ の展開・分割・書き出し・最初のノードの読み込み・GPU への転送）
- **AC-3** 設計の案を2つ以上比べた ADR の草稿（`TaskSheets/ADR-0024-progressive-open.md`、状態「提案」）。少なくとも次を比べる:
  - (a) 変換と並行して、読み込んだ点から一様に間引いた「下見の点」をメモリに持ち、仮のレイヤーとして描く。変換が終わったら COPC のレイヤーに差し替えて下見を捨てる
  - (b) 変換の LOD の上の方の段（root に近いノード）を先に書き出して、変換の途中の COPC を開く
  - (c) COPC の初回表示そのものの改善（AC-1 の結果しだい）
  各案の、最初の点までの時間（推定）・メモリの上限の決め方・落ちないための仕組み・ADR-0019 との関係・Web と デスクトップの差・壊れやすい所
- **AC-4**（R2 で改訂）ADR-0024「メモリ」: 固定の上限ではなく、デスクトップは空きメモリ A から下見の目標点数 `clamp(A×4%÷20B, 50万点, pointBudgetMax)` を決め、逼迫したら 下見 → NodeCache（setPointBudget）→ 変換のメモリ内予算 の順に手放す（閾値 A < max(2GiB,10%)・max(1GiB,5%)・512MiB は推定）。
Web/Android は空きが取れないので、変換のメモリが先に問題になる前提で、下見は `min(400万点, pointBudgetMax/2)` に固定して悪化させない。

**R2 の変更**: レンダラに階層の差し替え `replaceLayerHierarchy` と `NodeCache.remove`・`NodeLoader.cancel` を足す案（コーディネーターの判断）、切り替えは COPC が下見と同じくらい描けてから、変換の入口 5 つの列挙（実装は中〜大）、PF-1 の受け入れ基準の案を ADR-0024 に書いた。

**確かめていないこと**: 下の ADR-0024「壊れやすい所」の 1〜6（特に、レンダラが平らなノードの集まりを階層として受けるか）。
