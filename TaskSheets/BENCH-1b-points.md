## 図郭名の付け方（データから読み取ったもの）

図郭名は `09LD` + 4桁の数字 `ABCD`。`09` は平面直角座標系IX系、`LD` は上位の区画で、
数字は 1/500 図郭（400m × 300m）の位置を表す。

- 行番号 R = `A`×10 + `C`、列番号 K = `B`×10 + `D`
- 例: `09LD2626` は R=22, K=66。`09LD2720` は R=22, K=70（`2629` の東隣は `2720`）
- K が増えると東、R が増えると南（Y 座標は R が増えると小さくなる。ヘッダーの範囲から）

これは公式の説明を読んだのではなく、渋谷55枚の名前の並びと、全タイルの座標範囲から
推定した規則。HEAD リクエストで R=10〜45、K=50〜92 の 1548 個を調べ、1510 個が実在した
（索引図 `indexmap23ku.zip`、約64MB の PDF は取っていない）。

## マージツールが複数フォルダを受け付けるか

**受け付けない**。`crates/pcv-convert/examples/merge_las_to_copc.rs` の入力は1つの文字列で、
`merge::collect_input_paths` がそれを「ディレクトリ」か「glob 1つ」として扱う。
2つのフォルダを同時には指定できない。回避案（どれも未実施）:

## 変換（段階1、2026-10-14）

入力165枚 → 1つのCOPC。**画面の計測はしていない**（描画のLODを別担当が変更中のため。合図待ち）。

### 手順とコマンド

1. マージツールは入力フォルダが1つなので、`data/tokyo-23ku-1b-all/` に165枚の**ハードリンク**を作った
   （`New-Item -ItemType HardLink`）。作成前後のCの空きは 120.86GB → 120.86GB で、増減なし。
2. 先頭ファイル（名前順の `09LD1684.las`）が EPSG:6677 を持つことを `scripts/las-header-report.ps1` で確認した。
   CRS が無い17枚は、ツールが「先頭のCRSとみなした」と一覧表示した（上の17枚と一致）。出力のWKTは JGD2011 / 平面直角IX系（EPSG:6677）。
3. 変換（release、`Start-Process` で子プロセスにして、500msごとに `PrivateMemorySize64` を、30秒ごとにCの空きを記録。
   空きが30GB未満になったら中止する見張り付き。中止は発動しなかった）:

```powershell
.\target\release\examples\merge_las_to_copc.exe `
  C:\rust\point-cloud-viewer\data\tokyo-23ku-1b-all `
  C:\rust\point-cloud-viewer\data\tokyo-23ku-1b.copc.laz --assume-missing-crs-is-first
```

### 結果（実行したコマンドの出力）

| 項目 | 値 |
|---|---|
| 終了コード | 0 |
| ツール内部の所要時間 | 3275.33 秒（約54.6分）。見張り側の計測は 3275.77 秒 |
| private memory のピーク | 423,694,336 B = **0.395 GiB**（ワーキングセットではない） |
| 出力サイズ | 13,114.39 MB（13,114,389,440 B） |

- ディスクは読み込み中に急に減り（約270秒で 120→60GB）、その後ゆっくり下がる。968秒付近で約9GB戻った。
  一時ファイル（`%TEMP%` の `.copc-writer-spill.*`）だけの量は**分けて測っていない**。
  変換後の空きは 105.63GB で、13.1GBの出力以外の一時ファイルは消えていた。
  なお `%TEMP%` には変換開始前（8:59）の `.copc-writer-spill.*.part`（11.4GB）が残っており、これは今回のものではない（所有者が消してよいか判断）。
- 段階ごとの内訳（timings）: このツールは出さない（出るのは「マージ完了」の秒数と出力サイズのみ）。そのため読み込み/書き出しの時間の割合は**不明**。
