## 図郭名の付け方（データから読み取ったもの）

図郭名は `09LD` + 4桁の数字 `ABCD`。`09` は平面直角座標系IX系、`LD` は上位の区画で、
数字は 1/500 図郭（400m × 300m）の位置を表す。

- 行番号 R = `A`×10 + `C`、列番号 K = `B`×10 + `D`
- 例: `09LD2626` は R=22, K=66。`09LD2720` は R=22, K=70（`2629` の東隣は `2720`）
- K が増えると東、R が増えると南（Y 座標は R が増えると小さくなる。ヘッダーの範囲から）

これは公式の説明を読んだのではなく、渋谷55枚の名前の並びと、全タイルの座標範囲から
推定した規則。HEAD リクエストで R=10〜45、K=50〜92 の 1548 個を調べ、1510 個が実在した
（索引図 `indexmap23ku.zip`、約64MB の PDF は取っていない）。

## 画面での計測（段階2、2026-10-14）

### 条件

- GPU: `adapter.info` = `{"vendor":"nvidia","architecture":"lovelace","description":"","isFallbackAdapter":false}`（SwiftShader ではない）。Web・デスクトップとも同じ値
- Web: `npm run build:wasm && npm run build` → `npx vite preview --port 4611`。ファイルは自作の Range 対応 Node HTTP サーバー（ポート 4612、
  scratchpad の `serve.mjs`）から URL で開いた。Playwright の画面あり Chromium（`channel: "chromium"`、`headless: false`）、
  引数 `--enable-unsafe-webgpu --disable-background-timer-throttling --disable-renderer-backgrounding --disable-backgrounding-occluded-windows`、
  `bringToFront`、1600x900。1ファイル・1視点ごとにブラウザを起動し直した
- 視点: 全体 = 開いた直後の既定カメラ（distance 7794）。街区 = `target [-12000,-37800,40] distance 400 pitch 0.6 yaw 2.0`、
  通り = `distance 40 pitch 0.1 yaw 0.5`（街区・通りは両ファイルで同じ世界座標。渋谷のデータの範囲内）

  **ウィンドウは既定の 800x600**（Web の 1600x900 より小さい）。ファイルを開くダイアログは PowerShell の `SendKeys` でパスを入れて Enter。
  時間は Enter を送った時刻から最初に点が出るまで（ダイアログが閉じる時間・`open_copc` を含む）
- スクリプトは scratchpad（リポジトリ外）: `bench1b\m2.mjs`（Web）・`bench1b\d.mjs`（デスクトップ）

### 3倍になって、何が比例し何が比例しないか

コーディネーターの予想: 「開く時間・描画の fps・メモリは点数にほぼ依存せず、全体を見下ろしたときの読み込み時間だけが伸びる」。**数値での判定:**

| 予想 | 判定 | 根拠 |
|---|---|---|
| 開く時間は点数に依存しない | **合っている**（点数3.03倍に対し、Web 0.5〜1.3 秒でどちらも同程度。デスクトップ 4.46 s と 3.90 s で 1.14倍） | 上の表。ヘッダー・ルート階層の読み込みだけで開くため |
| メモリは点数に依存しない | **ほぼ合っている**（GPU プロセスは 10億点のほうが小さい: 街区 830 対 1411 MiB。レンダラーは 380〜575 対 424〜508 で同程度） | 点予算の上限（2684万点）で頭打ち。GPU 側の差の理由は未調査 |
| 描画の fps は点数に依存しない | **一部外れた**。同じ約 2680万点を描いているのに、10億点のほうが遅い場面がある（Web 街区 28 対 46 fps、通り 42 対 55 fps、デスクトップ街区 27〜40 対 55〜58 fps、デスクトップ全体 8〜13 対 60 fps） | 中央値は Web で同じ（16.7 ms）だが p95・最後の fps は 10億点が悪い。**原因は未調査**。ばらつきが大きい（上の再測定）ので、傾向としてしか言えない |
| 全体を見下ろしたとき読み込み時間だけが伸びる | **確認できなかった**。全体視点の点数は 3.4M 対 2.9M（1.17倍）、ノード 35 対 30 で、1秒以内に表示された。LOD A の打ち切りが効いて、全体視点では点数が点数に比例して増えない | 街区・通りのように「近づく」視点では点数が上限まで読まれ、時間が伸びた（街区 1.06倍、通り 2.2倍、デスクトップ街区 1.8倍）が、**1回ずつの測定でサーバー律速・カメラ干渉の疑いがあり、3倍に比例するとは言えない** |

まとめ: 開く時間・メモリは、点数が3倍になってもほぼ変わらなかった。到達点数は点予算（2684万）で決まり、ファイルの点数ではない。
読み込みにかかる時間は伸びる向きだが、点数比（3.03倍）に比例してはいない（街区 1.06倍、通り 2.2倍）。fps は 10億点のほうが悪い傾向（原因未調査）。
