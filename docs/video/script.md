# アプリ紹介動画 台本（技術者向け・ナレーションあり・3〜4分）

- 方針: **アプリの紹介**。何ができるかを見せ、技術は「なぜそれができるのか」を短く添える程度にする
- 数値はすべて**開発機（Core i5-14600K / RAM 31.8GB / RTX 4070 / Windows 11）での実測値**。動画内でもそう言う
- 出典は各数値の横に `（記録: …）` で示した。収録前に記録と食い違いがないか確かめること
- 開発のつまずきの話は、この動画には入れない（別の動画にするなら、旧版の台本は git の履歴にある）

## 収録の前に

### 使うデータ

**数億点規模で、利用条件がはっきりした公開データを用意する**（autzen は 1,065万点で、つかみには小さい。sofi は利用条件が未確認）。
候補: 静岡県「VIRTUAL SHIZUOKA」の点群、東京都のデジタルツインの点群、USGS 3DEP、AHN。**ライセンスと出典表示の書き方を公式の資料で確かめてから使う。**

| データ | 動画での扱い |
|---|---|
| 公開データ（数億点、上の候補から） | つかみと大規模の場面。**出典を画面に表示する** |
| autzen-classified.copc.laz（1,065万点、Watershed Sciences 取得・Hobu 分類） | 分類の着色を見せる場面に使ってよい。出典を表示する |
| points-jack_he.copc.laz、beer.laz、sofi.copc.laz | **使わない**（出どころか利用条件が未確認） |

### 準備

- Windows 版の最新の Release、Android 版の APK、Web 版（https://dotob9.github.io/point-cloud-viewer/）
- 変換の実演用に、変換済みのキャッシュを消しておく（設定画面の OPFS の使用量から）
- 画面は 1920×1080。他社製品の画面は映さず、他社製品より優れているとは言わない
- 未実装の機能（計測・断面など）は「できる」と言わない

## 1. つかみ（0:00〜0:20）

**画面**: 数億点の点群を開く → 一瞬で全体が出る → 見ている場所から細部が詰まっていく → カメラを回して寄る

**字幕**: ○○ GB / ○○○,○○○,○○○ points（使うデータに合わせて記入）

> 数億点の点群も、一瞬で開いて、見ている場所から細かく表示します。
> 点群ビューア、Point Cloud Viewer です。

---

## 2. どこでも動く（0:20〜0:45）

**画面**: 同じ点群を Windows 版 → Android のタブレット → ブラウザの順に映す

**字幕**: Windows / Android / Web ── Tauri + Rust + WebGPU

> Windows でも、Android のタブレットでも、そしてインストールなしでブラウザでも動きます。
> 中身は Rust と WebGPU で、3つとも同じコードで描いています。

---

## 3. 開けるもの（0:45〜1:30）

**画面**: ファイル選択で LAZ を選ぶ → 変換の進捗 → 完了 → 表示。続けて PLY か PCD も開いてみせる

**字幕**: COPC / LAS / LAZ / E57 / PLY / PCD

> 開けるのは COPC、LAS、LAZ、E57、PLY、PCD です。
> COPC 以外のファイルは、開くときに一度だけ COPC に変換して保存するので、2回目からは一瞬で開きます。
> 変換は進捗が見えて、途中で止めることもできます。

**画面**: Web 版で変換 → 終わったら「変換の内訳」が出る

**字幕**: ブラウザだけで変換 ── WebAssembly + OPFS

> ブラウザ版でも変換できます。ファイルをどこかにアップロードすることはなく、手元のブラウザの中だけで変換します。

---

## 4. 見え方を変える（1:30〜2:20）

**画面**: 着色を 標高 → 強度 → 分類 → RGB と切り替える（分類は autzen で）

> 色は、RGB、標高、強度、分類から選べます。色の情報を持たない点群でも、標高で色を付ければ形が分かります。

**画面**: 陰影（EDL）のオンとオフを切り替える

> 陰影を付けると、色が無くても凹凸が読めます。

**画面**: 設定画面で中央優先度を 0 → 4 に切り替え、同じ視点から読み込み直す

> 細かく読み込む順番は、画面の中央を優先します。見たい場所から先に、はっきりします。

**画面**: タブレットで1本指で回転、2本指でズームとパン

> タブレットでは指で操作できます。

---

## 5. なぜ速いのか（2:20〜3:10）

**画面**: 図「COPC の中身」（ヘッダーと hierarchy、その後ろにノードごとのかたまり。octree の木）

**字幕**: COPC（Cloud Optimized Point Cloud）

> 速さの秘密は、COPC という形式です。点が木の構造、octree の順に並び、
> どの部分がファイルのどこにあるかの一覧が入っています。開くときに読むのはこの一覧だけで、
> あとは見ている場所に必要な部分だけを読み込みます。

**画面**: 実測の表

| ファイル | 大きさ | 開く時間 | ピークメモリ |
|---|---|---|---|
| 1,065万点 | 78MB | 11.1ms | 9MB |
| 3.64億点 | 2.03GB | 32.0ms | 13MB |

（記録: `TaskSheets/M1-point-rendering.md`。撮影に使うデータで測り直して差し替えてよい）

> ファイルが25倍大きくなっても、開く時間とメモリはほとんど変わりません。

**字幕**: 点予算をフレーム時間で自動調整（AIMD 制御）

> 一度に描く点の数は、端末の重さに合わせて自動で調整しています。

**画面**: 実測（デスクトップの変換）

| | 時間 | メモリ |
|---|---|---|
| 3.64億点 → COPC | 171秒 | 0.23GiB |

（記録: `TaskSheets/M4-import-and-conversion.md` の M4-9）

> 変換も、メモリに収まらない大きさのデータを少しずつ処理するので、数億点でもメモリはわずかです。
